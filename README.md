# Fish&Trip

Інтернет-магазин туристичного та рибальського спорядження на Laravel і Filament.

## Запуск

```bash
docker compose up -d
php artisan migrate --seed
php artisan catalog:cache-warm --fresh
composer run dev
```

`composer run dev` запускає веб-сервер, Vite, перегляд логів і загальний обробник черги. Кнопка перегенерації кешу в адмінці додатково запускає власний короткоживучий worker автоматично.

- Магазин: http://127.0.0.1:8000
- Адмінка: http://127.0.0.1:8000/admin

Дані адміністратора:

```text
admin
admin
```

## Docker, MySQL і Redis

Проект використовує локальні Docker-сервіси:

- MySQL: `127.0.0.1:3307`
- Redis: `127.0.0.1:6379`

Параметри бази:

```text
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3307
DB_DATABASE=kubii
DB_USERNAME=kubii
DB_PASSWORD=kubii
CACHE_STORE=redis
REDIS_HOST=127.0.0.1
```

Перший запуск:

```bash
docker compose up -d
php artisan migrate --seed
php artisan catalog:cache-warm --fresh
```

## Імпорт IBIS Gear

Каталог можна повністю оновити командою:

```bash
php artisan feed:import-ibis --replace
```

Команда сама завантажить XML-фід IBIS Gear. Для повторного локального запуску вже завантаженого файла можна передати `--file=/tmp/ibis-gear-feed.xml`.

## Redis-кеш

Меню каталогу, категорії та фасети фільтрів кешуються через Laravel Cache у Redis. Прогріти кеш по всіх активних категоріях:

```bash
php artisan catalog:cache-warm --fresh
```

Статистика кліків по фільтрах накопичується без очищення кешу на кожен клік. Раз на годину Laravel Scheduler запускає `catalog:cache-warm --fresh`, щоб застосувати новий порядок фільтрів і прогріти Redis пачкою.

Оновлення кешу працює за blue-green схемою: команда спочатку прогріває нову приховану версію кешу, сайт весь цей час читає стару версію, і тільки після успішного завершення прогріву перемикається на нову. Старі ключі залишаються в Redis до завершення TTL і видаляються автоматично.

Для локальної розробки тримайте окремий процес:

```bash
php artisan schedule:work
```

На сервері додайте cron для scheduler:

```bash
* * * * * cd /path/to/project && php artisan schedule:run >> /dev/null 2>&1
```

Для середовища, де Redis може бути тимчасово недоступним, можна використати `CACHE_STORE=failover`: Laravel спробує Redis, потім database cache.

Повне перезаповнення демонстраційними даними:

```bash
php artisan migrate:fresh --seed
```
